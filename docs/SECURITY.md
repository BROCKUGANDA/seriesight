# Seriesight Security Notes

1. **Server-side credentials only.** `GRID_API_KEY` is read exclusively inside `src/lib/providers/grid/grid-client.ts` (server modules). It never reaches browser JavaScript, network responses, or logs.
2. **Environment secrets.** `.env` is git-ignored; `.env.example` documents the optional variable without values.
3. **Outbound requests and SSRF.** GRID provider requests pass `assertUrlAllowed`: HTTPS + explicit host allowlist (`api-op.grid.gg`). Integration webhook deliveries can target arbitrary HTTPS hosts and loopback addresses; there is no DNS/IP-range filtering. Do not expose webhook configuration or delivery to untrusted users, and enforce approved-destination egress controls before any public deployment.
4. **Input validation.** Every mutation validates with Zod before touching services; query parameters are validated with `parseQuery`.
5. **Output encoding.** React escapes by default; no `dangerouslySetInnerHTML` is used anywhere.
6. **SQL safety.** All persistence flows through Prisma parameterized queries; no string-built SQL.
7. **Request throttling.** Authentication uses database-backed 15-minute counters (100 per source bucket and 15 per account). By default all callers share a source bucket; enable `TRUST_AUTH_PROXY` only behind an audited proxy that overwrites forwarded addresses. Broad API rate limiting is still needed. GRID uses bounded retries and a circuit breaker; draft version checks separately protect consistency.
8. **Error hygiene.** Unknown route errors are logged server-side and returned as generic `INTERNAL_ERROR` envelopes; no stack traces or internals are exposed. Every typed error carries a stable code, retryability and a recovery action.
9. **Authorization.** Coach registration requires `AUTH_INVITE_CODE`; passwords use scrypt with random salts. Random 256-bit session tokens are stored only as SHA-256 digests, expire after 12 hours, rotate at sign-in and are revoked at logout. Production cookies are `__Host-` prefixed, Secure, HTTP-only and SameSite=Lax. API access requires a server-resolved session, mutations require the configured `APP_ORIGIN`, and draft services enforce workspace ownership. Each demo session gets a new sandbox. No email verification or password recovery is implemented yet. Auxiliary coaching notes are memory-only and reset on account changes; old browser-local records are no longer loaded.
10. **Data governance.** No licensed GRID raw data, credentials, or private data in fixtures/screenshots; fixture data is independently authored and permanently labelled. Database schema is not treated as retention permission (see GRID_INTEGRATION.md).
11. **File uploads.** None exist in the MVP — no arbitrary file import surface is exposed.
12. **Experimental APIs disabled.** Billing and integration routes return 403 for authenticated callers (401 without a session). Their global stores lack workspace ownership; keep them blocked until isolation, payment security and outbound egress controls are reviewed.
13. **Dependency audit.** The lockfile records resolved dependency versions but does not guarantee they remain secure. Run the dependency and container vulnerability scans against current advisories before each release.
14. **Previously reported advisories.** A prior audit noted high-severity advisories involving `sharp` and its native dependencies. Their current status has not been verified here; confirm against current scanner results and upgrade to a fixed compatible version before deployment if any remain open. `sharp` is used by Next.js for image optimization, so do not treat the absence of user image uploads as eliminating dependency risk.
15. **Secrets handling during release.** Deployment secrets (`GRID_API_KEY`, `PROD_DATABASE_URL`) live only in machine-local `.env` (git-ignored, untracked since the hygiene commit) or in the hosting secret store — never in Git history, fixtures, or CI logs.
