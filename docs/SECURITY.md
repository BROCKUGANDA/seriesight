# Seriesight Security Notes

1. **Server-side credentials only.** `GRID_API_KEY` is read exclusively inside `src/lib/providers/grid/grid-client.ts` (server modules). It never reaches browser JavaScript, network responses, or logs.
2. **Environment secrets.** `.env` is git-ignored; `.env.example` documents the optional variable without values.
3. **Outbound requests and SSRF.** GRID provider requests pass `assertUrlAllowed`: HTTPS + explicit host allowlist (`api-op.grid.gg`). Integration webhook deliveries can target arbitrary HTTPS hosts and loopback addresses; there is no DNS/IP-range filtering. Do not expose webhook configuration or delivery to untrusted users, and enforce approved-destination egress controls before any public deployment.
4. **Input validation.** Every mutation validates with Zod before touching services; query parameters are validated with `parseQuery`.
5. **Output encoding.** React escapes by default; no `dangerouslySetInnerHTML` is used anywhere.
6. **SQL safety.** All persistence flows through Prisma parameterized queries; no string-built SQL.
7. **Request throttling.** Authentication uses database-backed 15-minute counters (100 per source bucket and 15 per account). Every non-health API request also consumes a shared 60-second bucket (`API_RATE_LIMIT_PER_MIN=600`, `AUTH_RATE_LIMIT_PER_MIN=60`, `LEADS_RATE_LIMIT_PER_MIN=20`); denials return `429 RATE_LIMITED` with `Retry-After`. Enable `TRUST_AUTH_PROXY` only behind an audited proxy that overwrites forwarded addresses; otherwise all callers share one bucket by design. GRID uses bounded retries and a circuit breaker; draft version checks separately protect consistency.
8. **Error hygiene.** Unknown route errors are logged server-side and returned as generic `INTERNAL_ERROR` envelopes; no stack traces or internals are exposed. Every typed error carries a stable code, retryability and a recovery action.
9. **Authorization.** Coach registration requires `AUTH_INVITE_CODE`; passwords use scrypt with random salts. Random 256-bit session tokens are stored only as SHA-256 digests, expire after 12 hours, rotate at sign-in and are revoked at logout. Production cookies are `__Host-` prefixed, Secure, HTTP-only and SameSite=Lax. API access requires a server-resolved session, mutations require the configured `APP_ORIGIN`, and draft services enforce workspace ownership. Each demo session gets a new sandbox. No email verification or password recovery is implemented yet. Auxiliary coaching notes are memory-only and reset on account changes; old browser-local records are no longer loaded.
10. **Data governance.** No licensed GRID raw data, credentials, or private data in fixtures/screenshots; fixture data is independently authored and permanently labelled. Database schema is not treated as retention permission (see GRID_INTEGRATION.md).
11. **File uploads.** None exist in the MVP — no arbitrary file import surface is exposed.
12. **Billing API boundary.** Billing checkouts, verification, demo settlement and reversals require an `owner` role in the active workspace; payment history requires `analyst`. Ledger reads and writes are filtered by workspace id, so one tenant can never see or mutate another tenant's intent. Integration management APIs remain opt-in (`INTEGRATION_APIS_ENABLED`) until webhook egress and inbound adapter authorization are reviewed.
13. **Dependency audit.** `bun audit` runs in CI and must report zero vulnerabilities. The current baseline has no known advisories across 696 resolved packages; unused dependency trees (`next-auth`, `next-intl`, `@mdxeditor/editor`, `@reactuses/core`, `z-ai-web-dev-sdk`, `react-syntax-highlighter`) were removed. Prisma 6's `deepmerge-ts` and `effect` ranges are pinned forward with package overrides until a Prisma major upgrade is planned.
14. **Runtime dependency posture.** Next.js 16.4.6 and `sharp` 0.35.5 include the fixes for the previously reported critical advisories. Re-run both dependency and container scans before deployment; a clean lockfile alone does not cover base images.
15. **Background dispatch.** The in-process integration scheduler is disabled in production (`SERIESIGHT_DISPATCH_INTERVAL_MS=0`) by default. Event, endpoint and notification records are now tenant-scoped, but operators must still review outbound destinations before enabling the loop or integration management APIs.
16. **Tenant isolation.** Every coach receives a personal organization and workspace; team memberships carry `owner`, `coach`, `analyst` or `viewer` roles. Session workspace id is server-owned and switchable only after membership verification. Drafts, GRID history, provider connections and payment intents are keyed by workspace. Integration events, endpoints and notifications carry a workspace id and webhook fan-out only matches same-tenant endpoints.
17. **Account recovery.** Verification and reset tokens are 256-bit random values stored only as SHA-256 digests, expire after 24 hours / 1 hour, and are single-use. A successful reset revokes every existing session for that account. Reset requests return a generic response for unknown emails. Delivery uses Cloudflare Email Service with a fixed `api.cloudflare.com` endpoint; development can run without credentials, production fails closed.
18. **Operational alerting.** `ALERT_WEBHOOK_URL` is restricted to HTTPS and an explicit host allowlist, signed with `ALERT_WEBHOOK_SECRET`, and throttled to one alert per event per minute. Payloads contain event metadata, never request bodies, cookies or credentials. Structured logs remain the source of truth.
19. **Secrets handling during release.** Deployment secrets (`GRID_API_KEY`, `PROD_DATABASE_URL`, `CLOUDFLARE_EMAIL_API_TOKEN`, `ALERT_WEBHOOK_SECRET`) live only in machine-local `.env` (git-ignored, untracked since the hygiene commit) or in the hosting secret store — never in Git history, fixtures, or CI logs.
